# VAULTX — SMS OTP Verification & Forgot PIN Recovery Integration Guide

## Current Status
- **Mobile-number ownership OTP verification is NOT enabled** because no external SMS provider credentials are configured in Render or Supabase.
- **`users.mobile_verified` defaults to `false`** for all accounts rather than faking ownership with hardcoded/mock OTPs.
- **Unauthenticated "Forgot PIN" resets are intentionally NOT exposed** until SMS OTP verification is configured, preventing unauthorized account takeover or account enumeration.

## Recommended Provider Integration Architecture (Future Phase)

### 1. Required Environment Variables (Set Only in Cloud Secret Managers)
Never commit credentials to Git or paste them in chat.

Option A — Twilio Verify:
- `SMS_PROVIDER=twilio_verify`
- `TWILIO_ACCOUNT_SID`
- `TWILIO_AUTH_TOKEN`
- `TWILIO_VERIFY_SERVICE_SID`

Option B — Twilio Programmable SMS / MSG91 with App-Managed Hashed OTPs:
- `SMS_PROVIDER=twilio` (or `msg91`)
- Provider API key/token + sender ID
- `OTP_HMAC_SECRET` (32+ byte random secret for HMAC-SHA256 OTP storage)

### 2. Proposed Schema Addition (`public.otp_challenges`, when ready)
- `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
- `mobile_number VARCHAR(20) NOT NULL`
- `purpose VARCHAR(24) NOT NULL` (`verify_mobile`, `reset_pin`)
- `otp_hash TEXT NOT NULL` (HMAC-SHA256 / SHA-256 salted hash — never plaintext)
- `attempts INTEGER NOT NULL DEFAULT 0` (lock/invalidate after 3 wrong guesses)
- `expires_at TIMESTAMPTZ NOT NULL` (5 minutes TTL)
- `consumed_at TIMESTAMPTZ` (single-use enforcement)
- `resend_available_at TIMESTAMPTZ NOT NULL` (60s cooldown)

### 3. Security Rules When Enabling Recovery
1. Always accept normalized E.164 mobile number only, and return generic messages (`"If this mobile number is registered, an OTP has been sent."`) to block user enumeration.
2. Require verified OTP $\rightarrow$ short-lived single-use recovery token (`5 min`) before accepting `newPin` + `confirmPin`.
3. Immediately call session invalidation for that `userId` (`SessionManager`) upon any PIN reset so active stolen sessions are terminated.
4. Rate-limit both OTP dispatch (per-IP + per-mobile cooldown) and OTP verification.
